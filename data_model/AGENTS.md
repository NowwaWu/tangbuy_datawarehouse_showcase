# data_model 本地规范

本目录是 Demo Cross-border Commerce 数仓的模型标准中心，只维护 OneData 口径、命名、规划和指标定义，不写 DDL、ETL 或临时取数 SQL。

## 目录职责

`数据标准/` 存放全仓通用数据标准，字段英文缩写、业务中文名和词根解释以这里为准。

`数仓规划/` 存放数据域、业务过程、源表归类、主题域、数据集市和业务取数路径。

`数据指标/` 存放指标体系，包括原子指标、修饰词、时间周期、派生指标和复合指标。

## 词根维护速查

常用词根以 `命名词典.md` 为准：`amt` 金额、`fee` 费用、`cnt` 次数/数量、`stat` 状态、`cd` 编码、`nm` 名称、`crt` 创建、`upd` 更新、`del` 删除、`item` 商品、`shop` 店铺、`usr` 用户。

流程和业务动作类词根常见为：`xtra` 补款/额外、`cmsn` 佣金/返利、`srv_fee` 服务费、`acty` 活动、`asgn` 分配、`dflt` 默认、`alloc` 分摊、`rtn` 退货、`cxl` 取消、`exch` 换货、`frz` 冻结、`rjt` 拒绝、`tkn` 令牌、`inst` 安装、`rgn` 地区。

如果 `AGENTS.md` 速查与 `命名词典.md` 不一致，以 `命名词典.md` 为准，并同步更新速查段落。

## 使用顺序

新增字段前，先查 `命名词典.md`。

新增表名前，先查 `数据域.md`、`业务过程.md`、`数据域明细.md`。

新增 ADS 表名前，先查 `数据集市.md` 和 `主题域.md`。

新增指标前，先判断它是原子指标、修饰词、派生指标还是复合指标，再更新对应文件。

响应业务取数问题前，优先查 `业务取数映射.md`，再判断是否需要补 DWS、ADS 或指标定义。

## 更新原则

不要发明词根。词典没有的英文缩写，先更新 `数据标准/命名词典.md`，再让下游表结构和 SQL 使用。

中文业务名和 English abbreviation 必须一一对应。改中文含义时，同步检查英文缩写是否仍然准确。

数据域、业务过程、源表归类要成组维护。新增来源表时，检查 `数据域.md`、`业务过程.md`、`数据域明细.md` 是否需要同步。

时间周期后缀只表达数据时间范围和快照方式，不表达计算过程。后缀语义变更必须先改标准，再改下游表。

下游 DDL、ETL、ADS 取数前，必须先确认本目录标准已更新。不要让 SQL 反向定义标准。

## 格式注意

多数 `.md` 标准文件表面像 CSV，实际常用 Tab 分隔；解析前先确认分隔符。

指标类文件可能包含 `# ======` 分节注释，自动处理时要跳过注释行。

`数据域明细.md` 和 `业务取数映射.md` 是 Markdown 混合格式，包含表格、说明和 SQL 片段，不适合直接当 TSV 解析。

`时间周期.md` 管指标周期；仓表存储策略 `_di/_df/_td/_1d/_nd` 还必须结合根 `AGENTS.md` 判断。

## 修改边界

本目录只定义标准、规划和口径，不承载临时分析逻辑。

不要在这里补写 `INSERT OVERWRITE`、建表语句或 DataWorks 调度说明。

不要复制根目录已有的分层命名、Zero-NULL、SQL 编码规范。这里只写 `data_model/` 的权威资料关系和维护规则。
