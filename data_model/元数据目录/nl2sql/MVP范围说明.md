# NL2SQL MVP 范围说明

> 本文用于固化 NL2SQL 第一阶段边界。后续 `allowed_tables.yml`、`metric_catalog.yml`、`sql_examples.yml`、`eval_cases.yml` 均以本范围为准。

## 一、范围结论

NL2SQL MVP 第一阶段只覆盖 **DS 订单运营自助查数**。

首版目标不是让业务方自由查询全仓，而是让运营同事围绕 DS 代发订单，用自然语言完成高频、低风险、口径明确的自助查数。

## 二、业务目标

支持运营侧快速回答以下类型问题：

| 查询类型 | 示例问题 |
|---|---|
| 核心指标 | 昨天 DS GMV 是多少？近 7 天 DS 订单量是多少？ |
| 平台分析 | 上个月 Shopify 的 DS GMV 是多少？TikTok 订单量趋势如何？ |
| 商品分析 | 近 30 天 DS GMV Top 10 商品有哪些？ |
| 店铺分析 | 上周订单量最高的店铺有哪些？ |
| 国家分析 | 近 30 天美国、英国、德国的 DS GMV 分别是多少？ |
| 退款分析 | 上个月 DS 退款金额是多少？退款率是多少？ |
| 趋势分析 | 近 30 天每天 DS GMV 和订单量趋势如何？ |

## 三、首版覆盖对象

| 类别 | 覆盖范围 |
|---|---|
| 业务域 | `trd` 交易域为主，少量关联 `itm`、`store`、`comm`、`pay` 维表 |
| 业务过程 | `ds_ord` DS 代发订单 |
| 查询粒度 | 日、平台、店铺、商品、国家、订单行 |
| 查询层级 | 优先 DWS，其次 DIM/DWD，原则上不直接开放 ODS；不再默认开放自制 ADS |
| 结果类型 | 聚合结果、趋势结果、Top N 排行、有限明细预览 |

## 四、首版指标范围

| 指标类别 | 指标 |
|---|---|
| GMV | DS GMV、平台 DS GMV、国家 DS GMV、商品 DS GMV、店铺 DS GMV |
| 订单 | DS 订单量、DS 子单行数、包裹数量 |
| 金额 | 采购金额、三方订单金额、退款金额、优惠金额、国内邮费 |
| 比率 | 退款率、客单价 |
| 排行 | 商品 GMV Top N、店铺 GMV Top N、国家 GMV Top N |
| 趋势 | 按天 GMV、订单量、退款金额趋势 |

## 五、首版维度范围

| 维度 | 说明 |
|---|---|
| 时间 | 按天、近 7 天、近 30 天、自然月、自然周 |
| 平台 | Shopify、TikTok、WooCommerce |
| 商品 | TangBuy 商品、三方平台商品 |
| 店铺 | 三方平台店铺、授权店铺 |
| 国家 | 收货国家优先，注册国家不作为默认订单国家口径 |
| 用户 | 仅支持聚合统计，不开放用户个人信息明细 |

## 六、首版默认查询层级

| 优先级 | 表 | 用途 |
|---|---|---|
| P0 | `dws_trd_ds_ord_line_td` | DS 订单行公共宽表，默认查询入口，含包裹费用分摊和物流信息 |
| P0 | `dws_trd_ds_ord_line_pkg_fee_td` | DS 订单行包裹费用分摊表，仅用于费用、重量、体积分摊分析 |
| P1 | `dim_itm_item_df` | TangBuy 商品维度补充 |
| P1 | `dim_itm_out_item_df` | 三方商品维度补充 |
| P1 | `dim_store_ds_shop_df` | 店铺维度补充 |
| P1 | `dwd_store_ds_shop_auth_rel_df` | 用户和店铺授权关系 |
| P2 | `dim_comm_country_df` | 国家区域维度补充 |
| P2 | `dim_pay_exch_rate_df` | 汇率维度，仅在需要币种换算时使用 |

如果上述表不能满足问题，第一阶段默认返回“当前 MVP 不支持”，不自动下钻到 ODS。

> `ads_ops_ord_ds_ord_line_td` 已废弃：该自制 ADS 未形成真实业务使用，不再作为默认查询入口、白名单事实表或新增需求依赖。历史线上表如需物理下线，需单独确认并走平台变更。

## 七、明确不覆盖范围

| 不覆盖内容 | 原因 |
|---|---|
| 网站原生订单、直购订单、备货订单 | 防止和 DS 订单口径混用 |
| 仓储履约全链路分析 | 属于后续履约主题，不纳入首版 |
| 分销佣金、代理提现 | 属于 `dist` 域专题，暂不纳入 |
| 用户增长和投放归因 | 口径依赖用户来源和行为事件，暂不纳入 |
| 财务账务、支付对账 | 权限和口径风险高，暂不纳入 |
| ODS 自由查询 | 源表重复、状态未清洗、JOIN 膨胀风险高 |
| 写操作、建表、改表、调度操作 | NL2SQL MVP 只做只读取数 |
| 手机号、邮箱、WhatsApp 等敏感明细 | 首版不开放个人敏感信息查询 |

## 八、默认安全边界

| 规则 | 要求 |
|---|---|
| SQL 类型 | 只允许 `SELECT` 和 `WITH` |
| 禁止语句 | 禁止 `INSERT`、`UPDATE`、`DELETE`、`DROP`、`ALTER`、`CREATE`、`TRUNCATE` |
| 表范围 | 只允许白名单表 |
| 时间范围 | 必须有明确时间范围或 `ds` 分区限制 |
| 返回行数 | 默认 Top N 或 `LIMIT 100`，明细预览最多 `LIMIT 1000` |
| 敏感字段 | 用户联系方式、社媒账号等默认禁查或脱敏 |
| 异常问题 | 口径不清时先反问，不猜测高风险口径 |

## 九、首版验收标准

| 验收项 | 标准 |
|---|---|
| 范围清晰 | 所有首版问题都能归入 DS 订单运营 |
| 表范围清晰 | 所有样例 SQL 只使用白名单表 |
| 指标清晰 | GMV、订单量、退款金额、退款率、客单价有标准口径 |
| 时间清晰 | 每个问题都有明确时间范围或默认时间规则 |
| 安全可控 | 越权表、敏感字段、无时间范围、大范围明细查询能被拦截 |
| 可评测 | Top 20 问题能沉淀为 `eval_cases.yml` |
